# AGENTS.md

## What this is

SSH docs server - 429 documentation sources (docs + API specs) served as searchable markdown over SSH. The source count is dynamic — `agents.sh` reads from the container at runtime. TypeScript fetcher normalises and writes docs; Docker image serves them via OpenSSH with `ForceCommand` routing. The two halves are separate: `src/` is the fetcher (Node.js/TypeScript), the SSH server is pure shell scripts + Docker.

## Commands

```bash
pnpm install              # Node 22+, pnpm 10
pnpm lint                 # typecheck only (tsc --noEmit)
pnpm test                 # unit tests (vitest, tests/unit/)
pnpm test:e2e             # Docker-based E2E tests (requires Docker, 3-min timeout)
pnpm test:smoke           # smoke tests against live container (DOCS_SSH_HOST=docs.erfi.io)
pnpm test:coverage        # unit tests with v8 coverage
pnpm generate:tools       # regenerate commands/tools.sh from TypeScript template
pnpm mcp:serve            # run the MCP-over-HTTP server locally (node+tsx; DOCS_ROOT=./docs, MCP_PORT=8081)
pnpm mcp:build            # compile the MCP server to a single Bun binary (dist/docs-mcp, musl)
pnpm fetch-docs           # fetch all doc sources into ./docs/ (parallel, cached by default)
pnpm docker:build         # fetch-docs (force refresh) + docker build
pnpm docker:build:cached  # fetch-docs (use cache) + docker build — fastest for iterating
pnpm release:patch        # bump version, commit, tag, push (triggers release workflow)
pnpm release:minor        # same, minor bump
pnpm release:major        # same, major bump
```

Run a single test file: `npx vitest run tests/unit/path/to/test.ts` (not `pnpm test -- path` — that runs all tests).

CI runs two parallel jobs on every push/PR: `test` (verify tools.sh sync → lint → test:coverage) and `e2e` (Docker-based E2E). Match locally when debugging CI failures. `release.yml` re-runs the full verification (tools sync + lint + unit + E2E) before building+pushing on tag pushes.

## Gotchas

- **ESM-only**: `"type": "module"` in package.json. All imports must use `.js` extensions (e.g. `import { Foo } from "./foo.js"`), even though source files are `.ts`.
- **tsx runtime**: scripts use `node --import tsx/esm`, not `ts-node` or compiled JS. No build step needed for dev.
- **`commands/tools.sh` is git-tracked but auto-generated**: never edit directly. Edit `src/commands/tools-template.ts`, run `pnpm generate:tools`, commit both. **CI verifies sync** via `git diff --exit-code` — a stale `tools.sh` fails CI.
- **Adding a doc source requires tagging it**: add to `src/application/sources.ts` AND to `SOURCE_TAGS` in `src/application/source-tags.ts`. `tests/unit/application/source-tags.test.ts` enforces a bijection — unit tests fail for untagged sources AND for tag entries referencing removed sources. Untagged sources are also excluded from `_source_groups.json` (which `agents.sh` uses to generate the "Related source groups" section).
- **`src/index.ts` writes `docs/_source_groups.json`** as a side effect of every fetch (see `src/index.ts:51-65`). Also regeneratable standalone via `src/commands/generate-source-groups.ts`.
- **`docs/` is gitignored**: generated at build time by `pnpm fetch-docs` or during Docker build. Don't commit docs.
- **`tsconfig.json` excludes `tests/`**: vitest handles test TypeScript separately.
- **Normaliser pipeline is 3-pass** (see `UpdateDocSets.ts:362-398`): Pass 1 picks ONE format converter via `supportsFormat()` (MdxNormaliser or HtmlNormaliser). Pass 2 tries extension-based fallback if pass 1 missed. Pass 3 runs all cleanup normalisers (`supportsFormat()` returns false) — currently MarkdownCleaner then ContentSanitiser. Array order in `src/index.ts:20` determines priority. When adding a normaliser, `supportsFormat()` return value decides which pass it runs in. A format converter may also return `null` to DROP the file from the doc set - `HtmlNormaliser` does this when Turndown output is both <1KB and <1% of a >1KB input (RSC/SPA app-shell pages, e.g. paginated listing pages): the page has no doc value, and keeping it as raw `.html` breaks the smoke-test invariant that markdown-capable sources contain only `.md` files. Dropped pages are logged per source during fetch.
- **Pass 1 is skipped when `DocFile.preNormalised` is true** (markdown content negotiation): when `HttpIngestor.fetchPage()` receives `Content-Type: text/markdown` from an upstream that honours `Accept: text/markdown, text/html;q=0.9` (acceptmarkdown.com spec / Cloudflare Markdown for Agents), it tags the DocFile so the format converter is bypassed — running Turndown on existing markdown corrupts it via escaping. Pass 3 cleanup still runs. Fallbacks: thin markdown body (<256B) → retry as HTML; 404/406 → retry forcing `Accept: text/html` (only one in-the-wild case: turborepo `/docs/openapi/*`).

- **Origin URLs (`[url]`, v0.28.0)**: every `DocFile` carries an optional `originUrl` captured at fetch time so agents can cite the public page, not just the corpus path. http sources: the fetched page URL (post-redirect); llms-full pages take the URL marker the dump carries (Vercel `source:`, Mintlify `Source:`, frontmatter `url:` as in nextjs, a url-only frontmatter block before the heading as in vitest/vite/bitwarden, a `URL:` line after the heading as in deno, the page's own "View as Markdown" link as in cloudflare; `.md` twins map to the HTML page via `pageUrlFromMarker`) and fall back to the source `url` without one (neon, timescaledb, react-native, svelte carry none; measured on the 2026-10-21 dumps: 7717 pages gained their own URL, not the 7338 in a830ddf's message); tarball, texinfo and openapi files are not 1:1 with pages and use the source `url`; RFCs map to `https://www.rfc-editor.org/rfc/rfc<N>.html` (RsyncIngestor); statuspage incidents to `/incidents/<code>`. git sources: `repoBrowseUrl()` in `src/shared/origin-url.ts` (GitHub `blob/HEAD`, GitLab `-/blob/HEAD`, Codeberg/Gitea/Forgejo `src/branch/<checked-out branch>`, unknown host -> no URL) computed from the ORIGINAL repo path (before `.mdx`->`.md`/rootPath stripping), unless the `DocSource` sets `publicUrl(repoRelPath)` (all in `src/application/public-urls.ts`): `erfi-technical-blog` (`lexicanumPublicUrl`, Starlight -> `https://erfi.dev/<slug>/`) and the four MicrosoftDocs Windows sources (win32-api, win32-docs, windows-drivers, windows-ddi -> lowercase `https://learn.microsoft.com/en-us/<path>`; link-graph's `normaliseUrl` lowercases learn.microsoft.com links, re-inserts `/en-us/` and maps the legacy `/windows/desktop/api/` to `/windows/win32/api/`, so their cross-references resolve: 2,018 cross-source edges on 2026-11-08). `erfi-personal-blog` stays on the GitHub blob fallback on purpose: its live URLs come from per-file `slug:` frontmatter, which a path-only mapper cannot reproduce. GitIngestor converter outputs (adoc, trash-guides, openapi-dir) have no origin (not 1:1 with repo files). **Persistence**: `UpdateDocSets` writes the per-source map into `<source>/.stamp.json` (`origins`), which only a real fetch rewrites, so cached runs keep it; `src/index.ts` then merges every stamp into root `docs/_origins.tsv` (`<source>/<relpath.md>\t<url>`, next to `_source_groups.json`; never inside `docs/<source>/`, which must stay markdown-only). **Tools**: `docs_read`/`docs_summary` (SSH templates + `src/mcp/docs-service.ts`) print `[url] <url>` under `[source]` when an entry exists (awk lookup prepended to the same command, split off by `splitOrigin()`); `docs_search` appends the URL as a 4th tab column via an awk join guarded by `[ -s /docs/_origins.tsv ]`. Missing file or entry = byte-identical output to pre-0.28. To add a site mapping for another git source, add a `publicUrl` function + unit test and verify two URLs return 200 live.
- **Link graph (`_links.tsv`, docs-ssh#5 phase 1)**: `src/application/link-graph.ts` runs at the end of every fetch (after `_origins.tsv`) and writes root `docs/_links.tsv` (`<from>\t<to>` corpus paths, sorted). Per markdown link (images and fenced code skipped): (1) resolve against the page's `[url]` origin and look the result up in the reverse origin map (an origin URL shared by 3+ files is a bulk fallback and ignored); (2) else match site-relative or page-relative paths against the same source's file paths by suffix, never down to a single dropped-to segment and never escaping the source with `../`. Absolute URLs resolve only through origins (site-host path matching was measured at 2.5k of 506k edges with slug-path false positives and removed). Targets linked from more than half of a 20+ page source are navigation and dropped. Two passes (paths + origins, then one file at a time): full corpus 2026-10-21 = 506k edges (17.8k cross-source), 41 s, 681 MB peak RSS, 46 MB file. Merged 2026-10-21 (5182f67, 9362f60), first live with the 2026-10-22 build. Read by `docs_links` (outgoing + backlinks of a page, titled from `_index.tsv`, 50 per list by default) on all three surfaces: `src/mcp/docs-service.ts`, both tool templates, and the dotfiles `docs-core.ts` port. One `rg -F` prefilter plus an exact-field awk check per call: 68 ms on the full 46 MB file. Feasibility: research/2026-10-21-link-graph.md.
- **Embedding neighbours (`_related.tsv`, docs-ssh#5 phase 2, 2026-10-30)**: `embed/embed.py` (Python; contract and tests in `embed/test_embed.py`, numpy + pytest only, run by ci.yml's `embed` job) embeds each page's first 2,000 chars with fastembed `BAAI/bge-small-en-v1.5` on CPU and writes the top 8 neighbours per page (dot product of normalised vectors; self and same-text duplicates excluded) as root `_related.tsv` (`<path>\t<n1>...`, most similar first). State is incremental: `docs-ssh-cache:/cache/embed/{pages.tsv,vectors.npy}` (float16, keyed by path + sha1 of the embedded text), so a night embeds only new or changed pages. `embed/ci-run.sh` runs it in a `python:3.12-slim` container on the router (4 CPUs, `EMBED_THREADS` = 4, nice 19; model cached in volume `docs-ssh-embed-model`) and copies `_related.tsv` into `docs/` before the image build; on failure it ships the previous file. build.yml gives it what the 175-min job leaves after a 30-min reserve, capped at 40 min (the budget covers embedding only; the neighbour pass, gate, image build, deploy and smoke come out of the reserve: builds 161/163 at 168k pages spent 493-1057 s in embed.py and ~10 min after it; embed.py logs `neighbour_secs` separately since 2026-11-04); leftovers carry over. Backfill finished 2026-11-03 (`pending=0`). `ci-run.sh` labels the container `docs-ssh-embed`, removes it on exit or TERM, and removes any leftover before starting: a container on the host daemon outlives a cancelled job (run 139's kept writing the cache for 2h15m after the runner killed the job, so build run 140 shipped without `_related.tsv`). First pass: dispatch `embed-backfill.yml` (default 7800 s budget: the runner kills every job at 3 h regardless of `timeout-minutes`; repeat until the log shows `pending=0`), then `build.yml` straight after - the shared `docker-push` group queues the build behind the backfill on Forgejo itself (verified 2026-10-30, Forgejo 16.0.6), so nothing outside the router has to wait and trigger it. Measured on the MS-01 2026-10-30: 667 pages/min single-process, no gain from fastembed `parallel` (research/raw/2026-10-30-embeddings/rate.py); the neighbour pass is quadratic: the per-row argpartition version took 169 s at 57k and 697 s at 114k pages on the router (2026-10-31, 12 CPUs, nice 19, idle); since docs-ssh#13 each block cuts candidates at the k-th largest 64-column chunk maximum instead, 156.5 s -> 30.9 s at 114k on the dev box with identical output on every row (research/raw/2026-10-30-embeddings/neighbours_time.py). Read by `docs_related` (default 8 rows) on the MCP service, both tool templates, and the dotfiles `docs-core.ts` port. Quality is judged against the search eval set (research/2026-10-30-search-eval.md).
- **Unknown source names get suggestions (docs-ssh#29)**: a `source=` or `/docs/<source>/` path naming a missing source returns `[unknown source "X" - did you mean: a, b]` instead of empty output. The SSH templates and the dotfiles docs-core.ts port prepend the busybox fragment `sourceGuardShell()` from `src/shared/source-suggest.ts` (prefix > suffix > substring, at most 6; docs-core.ts holds a hand copy); the MCP service uses `suggestSource()`, which adds Damerau-Levenshtein <= 2. `tests/unit/commands/generated-tools-syntax.test.ts` parses the generated tools.sh / tools-pi.sh, since quoting slips in the template literals only show in the output.
- **Clients outside this repo are forks, not generated**: the user's pi docs tools and the Claude Code MCP toolkit run `~/dotfiles/.pi/agent/extensions/lib/docs-core.ts` (shared by `docs.ts` and `.claude/mcp/toolkit.ts`), a hand-maintained port of the SSH templates. A tool-output change here (e.g. the v0.28.0 `[url]` header) does NOT reach them until docs-core.ts is ported too. The v0.28.0 `[url]` change was ported to docs-core.ts in dotfiles on 2026-09-30; keep the two in step by hand.

## MCP-over-HTTP server

A second transport (alongside SSH) so remote chat LLMs that can't SSH (Claude.ai custom connectors, ChatGPT connectors) can use the docs corpus. Streamable HTTP transport, MCP spec 2025-11-25. Additive - the SSH path is untouched.

- `src/mcp/docs-service.ts` - transport-agnostic core for the eight ops (search/read/grep/find/summary/sources/links/related). Identical rg/bat/find/awk pipelines and output formatting to the SSH builtins (`src/commands/tools-pi-template.ts`), but with a configurable docs root and a local `node:child_process` runner instead of an SSH hop. Injectable `Runner` makes it unit-testable without real binaries.
- `src/mcp/server.ts` - stateless MCP server (`sessionIdGenerator: undefined`, `enableJsonResponse: true`), eight `registerTool` wrappers (Zod schemas), `enableDnsRebindingProtection` with Origin/Host allowlists from env. Also serves the static landing page from `MCP_STATIC_DIR` for non-`/mcp` GETs, so one listener carries both surfaces (avoids Fly's one-service-per-external-port limit). `buildServer(service?)` takes an optional DocsService for test injection.
- `src/mcp/main.ts` - `listen()` entrypoint, split out so tests import `server.ts` without binding a port.
- **Stateless on purpose**: all eight ops are idempotent reads over a filesystem that's immutable per container lifetime, so no session store, horizontal-scalable, CDN-cacheable.
- **Bun-compiled**: `pnpm mcp:build` (and the Dockerfile `mcp-builder` stage, `oven/bun:1-alpine`) produce a single musl binary via `bun build --compile`. The Alpine runtime stage needs `libstdc++ libgcc` for it (already in the Dockerfile `apk add`). No Node/node_modules in the runtime stage.
- **Env**: `DOCS_ROOT` (/docs), `MCP_PORT` (8081 dev; entrypoint runs it on 8080), `MCP_HOST`, `MCP_STATIC_DIR`, `MCP_ALLOWED_HOSTS`, `MCP_ALLOWED_ORIGINS`, `VERSION` (serverInfo.version). Endpoints: `POST /mcp`, `GET /healthz`, `GET /*` -> static.
- Tests: `tests/unit/mcp/` - mock-runner command construction + safePath jail, in-memory-transport MCP wiring, real-binary integration (skips when `rg` absent).

## Architecture

- `src/index.ts` - fetch-docs entrypoint. Not the SSH server.
- `src/application/sources.ts` — canonical list of all doc sources. Two source types: `git` (sparse clone) and `http` (uses a discovery method — see "Adding a new doc source" below).
- `src/domain/` — value objects + port interfaces (`DocSource`, `DocIngestor`, `DocNormaliser`). Ports-and-adapters: implementations in `ingestors/` and `normaliser/`.
- `src/commands/tools-template.ts` — TypeScript source of truth for agent tools output. Generates `commands/tools.sh`.
- `src/shared/retry.ts` — `retryWithBackoff` + `backoffDelay` used by every network-dependent code path (HTTP fetches in `HttpIngestor`, HEAD freshness checks in `UpdateDocSets`, git clone/pull/ls-remote in `GitIngestor`). Jittered exponential backoff; `shouldRetry` predicate lets callers short-circuit on non-retryable errors.
- `commands/` — shell scripts for SSH built-in commands. Note: `src/commands/` (TypeScript, build-time) vs `commands/` (shell, runtime) are different dirs.
- `commands/lib/` — shared shell libraries: `colors.sh` (TTY detection), `log.sh` (JSONL audit logging), `cache.sh` (md5-keyed result caching in tmpfs).
- `commands/agents.sh` — dynamically generates agent instructions using live container data (source list, file counts). Supports formats: claude/cursor/gemini/skill/opencode.

## Docker / SSH runtime

- Two-stage `Dockerfile`: Node fetcher stage + Alpine runtime. `DOCS_PREBUILT=true` build arg skips the fetch by copying pre-fetched `docs/` from the build context — what `pnpm docker:build` and CI release use.
- **Query cache (`commands/lib/cache.sh`)**: results live in `/tmp/docs-ssh-cache` on the 16M `/tmp` tmpfs, owned by `docs`. Over `CACHE_MAX_KB` (8 MB) the cache is wiped before the next write; a capture that cannot be written, or that ran with the filesystem at 0 KB free, is discarded and the command re-runs uncached. Before this (2026-11-05) there was no eviction: the tmpfs filled, every new capture wrote 0 bytes, and the empty result was cached, so every docs search returned nothing. Manual wipe: `ssh servarr 'docker exec -u docs docs-ssh sh -c "rm -rf /tmp/docs-ssh-cache/*"'` (`-u docs`: container root has no CAP_FOWNER for the sticky /tmp).
- **SSH host keys persist (since 2026-10-19)**: `entrypoint.sh` runs `ssh-keygen` only when `/run/sshd` has no key. Production (`deploy/edge/compose.yaml`) mounts the named volume `docs-ssh_sshd` there, so the key survives redeploys: ed25519 `SHA256:3YL9x6H3uhpIcdyTAXYFspvUb2pe/mEaQvLnqBCZm10`. Before that it was a tmpfs and every deploy changed the key. Dotfiles docs-core.ts pins this key (`hostKeyOpts()`, StrictHostKeyChecking=yes); deleting the volume or rotating the key means updating `PINNED_HOST_KEY` there and the fingerprint here. The generated tools (tools.sh, tools-pi.sh, agents.sh) and the tests keep `StrictHostKeyChecking=no` because they also target local containers, whose keys are still per-container. A client with a stale entry: check `ssh servarr 'docker exec docs-ssh ssh-keygen -lf /run/sshd/ssh_host_ed25519_key.pub'` matches, then `ssh-keygen -R '[docs.erfi.io]:2222'`.
- **Query log (docs-ssh#5 phase 0, merged 2026-10-21 in b15b070; v0.28.3, the image live on 2026-10-21, still logs to the tmpfs - first live with the 2026-10-22 build)**: one JSONL file, `$DOCS_LOG_DIR/docs-ssh.jsonl` (default `/var/log`, a tmpfs; production sets `/var/lib/docs-ssh/log` on the `logs` volume). `entrypoint.sh` archives the previous file as `docs-ssh.<UTC start>.jsonl` on every start (nightly redeploy = about one file per day) and deletes archives older than 30 days; appends stop at 50 MB per file. SSH lines come from `commands/lib/log.sh`; the `echo ok` healthcheck from localhost is not logged. Clients may prefix a command with `: docsop <base64 json>; ` (dotfiles `docs-core.ts` does, with a per-process `sid`): `log-cmd.sh` strips it before caching and executing, and logs `op/q/path/source/pattern/direction/sid` as fields. MCP `tools/call` requests append `type: "mcp"` lines to the same file (`DOCS_LOG_FILE`, client = first X-Forwarded-For hop). SSH clients all show as the edge proxy IP (10.0.71.1); only `sid` tells sessions apart. Pull: `ssh servarr 'docker exec docs-ssh sh -c "cat /var/lib/docs-ssh/log/*.jsonl"'`.
- **Search eval set (docs-ssh#5, 2026-10-30)**: `research/2026-10-30-search-eval.md` + `research/raw/2026-10-30-search-eval/` (`extract.py` pairs logged searches with the next read per `sid`; `label.tsv` hand labels Y/fixed/absent with origin URLs; `baseline.py` scores live `docs_search` via the MCP endpoint). Keyword baseline: hit@5 23/30 on Y rows, 6/14 on fixed (agent-opened-the-wrong-page) rows. Drop rows naming private hosts before committing - the repo mirrors publicly. Paths of duplicate-title llms-full pages moved between builds until docs-ssh#12, so the set matches on origin URL too.
- **Duplicate titles in llms-full splits (docs-ssh#12, 2026-10-30)**: the first page with a title gets `<slug>.md`; later ones get `<slug>-<URL path segments>.md` (`limits-hyperdrive-platform.md`), so pages the vendor inserts earlier no longer rename them. The old `<slug>-<idx>.md` stays only as the fallback (no URL, or the dump lists the same URL twice - 119 cloudflare URLs on 2026-10-30). The first build after this renames roughly 1,300 cloudflare pages once (1,637 numeric-suffix paths in the live index on 2026-10-30; 318 under this rule on that day's dump, most of them real numbers like `http-2.md`).
- `entrypoint.sh` persists env to `/run/sshd/docs-ssh.env` because sshd drops container env. `log-cmd.sh` sources it back.
- `log-cmd.sh` is the `ForceCommand` — routes SSH sessions to interactive/builtin/exec handlers. Builtins are routed via `case` on first word of `SSH_ORIGINAL_COMMAND`.
- Three image-build-time scripts run in sequence: `build-index.sh` → `/docs/_index.tsv` (path + title + summary per file, what `docs_search` queries); `build-sources-json.sh` → `/docs/_sources.json` (powers landing page + banner); `build-health-check.sh` (warnings only, never fails the build).
- **/docs ships as 33 layers, not one** (docs-ssh#38, 2026-11-10): `src/commands/layer-buckets.ts` runs in the fetcher stage after `build-index.ts`, moves each source dir into bucket `fnv1a(name) % 32` under `/layers/NN/docs/` and the top-level files (`_index.tsv` etc.) into `/layers/top/docs/`, and zeroes every mtime. The runtime stage has one `COPY --from=fetcher /layers/NN/ /` per bucket plus `top`; an unchanged bucket is byte-identical to the previous build, so ghcr and servarr skip it. Before: one 1.17 GB layer (520 MB compressed) re-pushed and re-pulled on every build. Verified with two local builds differing in one source: only that bucket's layer, `top`, and the KB-sized layers after it changed. Keep: the 32 COPY lines match `BUCKETS` (unit test enforces); nothing may read doc mtimes at runtime (they are all 1970-01-01); the move falls back to copy+delete because overlayfs returns EXDEV for renaming a lower-layer dir.
- Command caching: identical read/search commands return cached results from tmpfs. Docs are static per container lifetime.
- **HTTP on 8080** (`entrypoint.sh`): the Bun-compiled `docs-mcp` binary serves BOTH the static landing page (`GET /`) and the MCP endpoint (`POST /mcp`) on 8080, falling back to busybox httpd (landing page only) if the binary is absent. Fly maps external 80/443 -> 8080; no separate MCP service/port. `GET /healthz` backs the Fly http_check.

## Adding a new SSH command

Add a `case` entry in `log-cmd.sh:44-59` and a script in `commands/`. Human-facing commands (like `help`) get `FORCE_COLOR=1`; machine-consumable commands (like `tools`) don't.

## Testing

- **Unit tests** (`tests/unit/`): mirror `src/` structure. No network or Docker needed.
- **E2E tests** (`tests/e2e/smoke.test.ts`): require Docker. 3-minute timeout. **Wipes `./docs/` at setup AND teardown** to build with mock fixtures — running this after `pnpm fetch-docs` or `docker:build:cached` will delete cached docs, forcing a re-fetch next time.
- **Smoke tests** (`tests/smoke/smoke.test.ts`): require a live SSH server. Test all sources, index, API specs, builtins, security. Default host is `localhost`; set `DOCS_SSH_HOST=docs.erfi.io` to test production.
- **Benchmarks** (`tests/benchmark/`): token efficiency tests, require a live SSH server.
- Four vitest configs: `vitest.config.ts` (unit), `vitest.e2e.config.ts`, `vitest.smoke.config.ts`, `vitest.bench.config.ts`.

## Release / Deploy

- **CI** (every push/PR to main): verify `tools.sh` in sync → lint → test:coverage. `test` and `e2e` jobs run in parallel.
- **Source health** (`.forgejo/workflows/check-sources.yml`, since 2026-10-05): `src/ci/check-sources-cli.ts` runs a cheap per-source probe (`src/ci/source-check.ts`) - git: blobless `--no-checkout` clone + `ls-tree` under `paths`; rsync: `--list-only`; http bulk (llms-full/openapi): download + split/convert + count; http URL methods: run `discover()`, apply urlPattern/urlExclude, fetch 3 spread sample pages. `fail` = the fetch would yield nothing (dead URL, 0 in-scope URLs, private repo); `warn` = degraded (redirects to another host, some samples fail); `tolerated` = a `TOLERATED_MISSING` source, reported but never red. The workflow runs `CHECK_STRICT=1`, so warns fail too: fix drift before it breaks. Sources whose pages redirect cross-host by design set `expectRedirects: true` (planet-postgres). The probe retries a 429 / 5xx / network error once; a sample still 5xx (or an archive.org 429) after the retry is noted but not counted, unless no sample fetched at all (ubuntu.com 500d one sample page on runs 82 and 85 while the nightly fetch got all 255) and serialises web.archive.org requests (four sources pin Wayback captures; archive.org 429s bursts). Push/PR touching the fetcher probes only sources whose `sources.ts` block changed (`CHECK_CHANGED_SINCE`); daily 00:30 UTC probes all ~429 (~5 min) before the 02:00 build; dispatch takes `only=a,b`. Run locally: `CHECK_ONLY=flyio node --import tsx/esm src/ci/check-sources-cli.ts`. Fix every `fail`; redirect warns mean point `url`/`discoveryUrl` at the final host (origin URLs and paths derive from `url`).
- **Floors / docs gate**: `src/ci/source-floors.ts` holds `SOURCE_FLOORS` (per-source minimum files), `API_OVERVIEW_SOURCES` and `TOLERATED_MISSING` (source -> reason+date, for an upstream that blocks us; akamai was removed 2026-10-19 - its Bot Manager blocks came and went and 9.7k pages never fit the deadline. A source an upstream blocks for good is removed, not tolerated. empty again: archwiki was in it for a few hours on 2026-11-05 after the wiki refused our WAN IP at the TLS handshake, docs-ssh#20). **Prefer an upstream bulk artifact over scraping**: archwiki now ingests Arch's `arch-wiki-docs` package (`discovery: "tarball"`, a `.pkg.tar.zst` decompressed with Node's built-in zlib zstd, `rootPath` into the archive, `publicUrl` maps each page to its wiki URL, `urlExclude` filters on that URL, and archive-relative `.html` links are rewritten to public URLs by `rewriteArchiveLinks` so the link graph resolves them; docs-ssh#21).
- **Refetch floor** (`minRefetchSeconds` on a `DocSource`): the source is skipped while its stamp is younger than the floor, even on `docsMaxAge=0` builds (fetcher change, manual refresh) - those otherwise re-scrape every source. Use it for large validator-less scrapes of hosts that ban aggressive clients (no source uses it since archwiki moved to its package; it was 7d at `pageConcurrency: 1`). To force one fetch, delete that source's `.stamp.json` from the docs cache. The post-deploy smoke AND the pre-build gate (`src/ci/gate-cli.ts`, a build.yml step after the cache save, before the image build) read it: the gate fails the build when any SOURCES entry is missing/empty or below its floor, so a broken fetch never replaces the live image (run 28 shipped without six sources). Remove a `TOLERATED_MISSING` entry once the source fetches again.
- **Fetch-level guards** (HttpIngestor): 0 URLs left after urlPattern/urlExclude throws (upstream moved its docs); >= 20 page failures that outnumber successes throws (rate-limit collapse) so the previous copy survives instead of a fraction. `parseRetryAfter` treats `Retry-After: 0` / past dates as no hint, never a 0ms wait. A degraded baseline (stamp written by a broken fetch) makes the fixed fetch read as >2x growth: dispatch build.yml with `regression_exempt=<source,...>` (env `DOCS_REGRESSION_EXEMPT`) to accept it once. A deliberate change to what a source fetches needs no exemption: the stamp records `configHash` (`sourceFingerprint()`: every DocSource field except name/description/tags and throughput knobs), and a changed hash skips the size guard for that fetch (docs-ssh#37: at32f405 grew 68 -> 307 after gaining PDFs and failed the v0.31.1 gate). Stamps written before 2026-11-08 have no hash, so the guard still applies to them once.
- **Build** (`.forgejo/workflows/build.yml`, since 2026-09-30 - replaced `release.yml` + `update-docs.yml`): ONE workflow for tag `v*` releases, the 02:00 UTC daily refresh and manual runs, all in the `docker-push` concurrency group. A plan step (`src/ci/plan-cli.ts` -> `planBuild` in `src/ci/build-plan.ts`, unit-tested in `tests/unit/ci/`) reads `docs/_build.json` (`fetchedAt`, `commit`) from the persistent cache and decides: tag = always build, fetch only if docs are >= 20h old or fetcher code (`FETCHER_PATHS`: src/ingestors, src/normaliser, src/application, src/domain, src/shared, src/index.ts, package.json, pnpm-lock.yaml) changed since that commit; schedule = skip the whole run when docs are < 20h old and fetcher code is unchanged (a release fetched them), else fetch; dispatch = like tag, input `refresh: true` forces a full refetch. Fetcher-code change -> `DOCS_MAX_AGE=0` (regenerate every source with the new code); otherwise a warm fetch with `DOCS_MAX_AGE=129600` (36h per-source trust window, git clones kept in `work/`). `verify` (tools.sh sync, lint, unit, e2e) gates tags only; schedule/dispatch build `main`, which CI already gated. Its steps are gated per step, never with a job-level `if`: Forgejo skips a job whose `needs` was skipped even under `if: !failure() && !cancelled()`, which made every daily refresh a silent no-op from 2026-10-01 to 2026-10-05. Then build with `DOCS_PREBUILT=true` -> push `latest` + date (+ semver on tags) to GHCR (`secrets.GHCR_TOKEN`) -> deploy through Composer (`COMPOSER_URL`/`COMPOSER_API_KEY`, async job poll) -> smoke against live. **Cache**: docker volume `docs-ssh-cache` on the router daemon (jobs drive the host daemon via the automounted socket), holding `docs/` and `work/`, moved with `docker cp` through a throwaway `alpine` container (no runner `valid_volumes` change needed). Saved right after a fetch, before the build, so a failed build/deploy never loses a fetch; swap is `*.new` then rename. Deleting the volume = next run is a cold fetch (~2h20m; the runner caps jobs at 3h). `docs/_build.json` also ships in the image (root `_*` files are excluded from source counts like `_origins.tsv`). **CI reachability (fixed 2026-09-30)**: Forgejo job containers cannot hairpin to the router's public IP. The build.yml deploy + smoke steps work because `composer.erfi.io` and `docs.erfi.io` resolve split-horizon to 10.0.10.1 (records in `~/infra/knotea/deploy/edge/config.yml`, knotea 3864bed) and the router nftables lets docker bridges reach 10.0.10.1 on :443 and :2222 (router ea2341f). v0.28.0's release run failed at the deploy step (curl exit 28) before that fix; the image was deployed by hand. `deploy/composer/` is HISTORY: the `docs-ssh-daily-update` Composer pipeline it describes was deleted 2026-08-31 (needed host-side builder setup); do not recreate it.
- **Version**: git tag is the single source of truth. `pnpm release:patch` bumps `package.json`, commits, tags, and pushes in one command. Landing page version injected from git tag at Docker build time; JS fallback fetches from GitHub tags API for self-hosted builds.

## Adding a new doc source

Add a `new DocSource({...})` to `src/application/sources.ts`. Pick a discovery method that matches how the upstream provides docs. The ingestor and normaliser are selected automatically by type/format matching. Discovery methods: `none`, `tarball`, `texinfo`, `pdf`, `llms-full`, `llms-index`, `llms-txt`, `sitemap`, `sitemap-index`, `toc`, `rss`, `openapi`, `openapi-dir`, `mediawiki`, `dokuwiki`, `mslearn`, `statuspage`, `incidentio`. Optional knobs: `tocDepth` (BFS depth for `toc` discovery; default 1 = single toc page; 2 = also crawl section index pages, e.g. openzfs-man), `pageConcurrency`, `deadlineMs`, `requestTimeoutMs`, `userAgent`, `skipMarkdownNegotiation`.

**Source-type preference order** (most → least reliable; pick the highest one the upstream actually offers):

1. **`type: "git"`** - clone+sparse-checkout the upstream's docs directory. Markdown direct from source. about half the sources use this. Survives upstream HTML/JS/CSS rewrites; only breaks when the repo path changes. Also supports `format: "html"` for repos shipping a checked-in Doxygen/tree of HTML (nuvoton-m480-bsp): GitIngestor walks `.html`, HtmlNormaliser converts and rewrites the path to `.md`.
2. **`type: "http"` + `discovery: "tarball"`** — single bulk archive (e.g. Supabase's `docs.tar.gz`). One fetch, no rendering, durable.
3. **`type: "http"` + `discovery: "llms-full"`** — single AI-targeted text dump from the upstream. Lighter than tarball, common pattern (Vercel, Cloudflare, Next.js, Bitwarden).
4. **`type: "http"` + `discovery: "openapi"` / `"openapi-dir"`** — for API specs. Converted to per-tag markdown by `openapi-converter.ts`.
5. **Other discovery methods** (`sitemap`, `toc`, `llms-txt`, `llms-index`, `rss`, `mediawiki`) — last resort. These all run page-by-page HTML scraping; brittle to upstream JS-rendering, format changes, missing pages. **HttpIngestor opportunistically sends `Accept: text/markdown, text/html;q=0.9` per the acceptmarkdown.com spec**; upstreams running Cloudflare's "Markdown for Agents" or supporting RFC 7763 content negotiation return clean markdown directly (verified live: cloudflare/cloudflare-blog/cloudflare-changelog/turborepo/prisma/resend/vercel-blog/ansible/patroni), bypassing Turndown via `DocFile.preNormalised`. Origins that don't support it return HTML normally - no behaviour change. Exception: origins whose WAF hard-rejects the markdown Accept header (verified: openvpn.net 503s every page carrying it, 200s without) need `skipMarkdownNegotiation: true` on the `DocSource` to force plain `Accept: text/html`. The same flag fixes upstreams whose negotiated markdown is worse than the HTML path: docs.kicad.org drops the page H1 (index titles read "Table of Contents") and keeps the Furo sidebar on kicad-python, while the HTML path titles from `<title>` and selects `<article>`.

**In-page chrome with no `<article>`/`<main>` split** - set `htmlContentClass` on the `DocSource`: HtmlNormaliser converts only the first element whose class list holds that class (div-balanced regex, `extractByClass`), titled from `<title>`, and skips the empty-conversion drop for it (a matched content element is a short page, not an app shell). Pages without the class take the normal cascade. Used by jlcpcb (`rich-preview-wrap`: help articles sit beside a ~60-line catalog sidebar inside `<main>`; without it 19 short articles were also dropped as app shells). Format converters receive the source as `normalise(file, source)`. MarkdownCleaner strips Sphinx/MkDocs heading permalinks (`[¶](#id "Link to this heading")`, thousands of lines in the 2026-11-04 corpus: openzfs-man, pfsense, kicad-python) and the Font Awesome U+F0C1 permalink glyph, drops a readthedocs breadcrumb block before the H1, and unescapes Turndown's `\_` and `\=` outside code so identifiers grep (`\[`, `\]`, `\*` stay escaped) for every source.

**Throttling a large rate-limit-prone scrape** — set `pageConcurrency` (per-page parallelism, default global `CONCURRENCY=15`) and `deadlineMs` (per-source hard deadline, default 10 min) on the `DocSource`. `cloudflare-blog` is the canonical case: blog.cloudflare.com sits behind Cloudflare's own bot/rate management, so the 15-wide default burst trips throttling and collapses the source to **zero files** (which then blows the 10-min deadline and silently lands an empty source in the image, since a fresh CI fetch has no prior baseline for the regression-threshold check to catch). Throttling to `pageConcurrency: 4` + `deadlineMs: 2_400_000` (40 min) fetches all ~3500 posts with zero retries/429s in ~25 min. Verify a single source without a full ~30-min build via `DOCS_ONLY=cloudflare-blog DOCS_OUT_DIR=/tmp/x DOCS_MAX_AGE=0 pnpm fetch-docs`.

**Origins that block the bot User-Agent** - set `userAgent` on the `DocSource` to override the UA for that source's page fetches (a shared `BROWSER_UA` const lives at the top of `sources.ts`). Verified cases: planalto.gov.br ECONNRESETs the docs-ssh UA, legisquebec.gouv.qc.ca and sso.agc.gov.sg 403 it; all 200 with a browser UA. Diagnose by replaying the failing URL with `node -e fetch(...)` once with the docs-ssh UA and once with a browser UA - an HTTP status change (or ECONNRESET -> 200) means UA filtering; a timeout in both (e.g. riksdagen.se's broken IPv6 route, which hangs undici but not curl -4) means find an alternate official host instead. For origins behind an AWS WAF JS challenge (eur-lex.europa.eu, legislation.gov.uk) or hard bot-blocking (legifrance.gouv.fr), no UA helps - use a Wayback Machine raw capture (`https://web.archive.org/web/<ts>id_/<url>` serves the original bytes; statutes change slowly so a pinned capture is fine, and the `privacy-laws-*` sources use this pattern). When an upstream blocks our WAN IP outright (docs.redhat.com since 2026-11-07, Akamai 403 for any UA, PDFs included), the 14 `rhel9-*` sources list pinned captures in `urls` with `pageConcurrency: 1` and `minRefetchSeconds` of 30 days: pinned captures never change, and archive.org drops connections under parallel load (4 of 14 guides failed at 3 pages per source). The source probe counts archive.org connection drops like its 429s (not as failures) and passes a source whose URLs are all pinned captures when archive.org is unreachable. Since 2026-10-06 such a URL is pathed as `<original-host>/<original-path>.md` and its `[url]` origin is the original page, not archive.org (`waybackOriginal()` in HttpIngestor). `urlSuffix` is not appended to a URL that already ends with it.

**rsync-only bulk mirrors (IETF RFCs)** - use `type: "rsync"` + `format: "txt"` with `url` set to the module spec (e.g. `rsync.rfc-editor.org::rfcs-text-only`). The RFC Editor retired its RFC-all tarball; rsync is the only sanctioned bulk channel and is incremental, so daily refresh transfers only new/changed files against the work-dir cache. `RsyncIngestor` syncs the module (with `-L` to materialise the module's symlinks); `TxtNormaliser` converts each `.txt` to fenced `.md` with an H1 parsed from the RFC header block (so build-index gets real title rows) plus the Abstract first paragraph as unfenced prose (feeds the search summary). Requires `rsync` in the Dockerfile fetcher stage. Limitation: ~1% of pre-1990 RFCs have freeform headers that defeat title extraction - they get a bare `# RFC <N>` heading and stay searchable by number.

**llms-full formats**: `splitLlmsFull` auto-detects Vercel (`<page>` blocks), Mintlify (`# Title` + `Source: <url>` per page, optionally one blank line apart as on docs.openwebui.com: docs.fly.io, bunny.net, paradedb, claude-code, open-webui - split only on that pair so `#` comments in code stay put, paths and `[url]` origins from the Source URL relative to `url`), frontmatter (pages without their own H1 get the frontmatter title; a `## <next title>` line before the next block, as in platform.claude.com, is dropped) and plain-heading styles. Over-long URL path segments are cut to 180 bytes plus a hash (filesystem name limit). For Mintlify sources set `url` to the host in the `Source:` lines.

**Docusaurus MDX import partials (immich)** - `resolveDocusaurusImports: true` on a `format: "mdx"` source inlines `import Foo from './_foo.mdx'` + `<Foo />` (absolute `/docs/...` and relative paths, partials = basename starting with `_`) and drops the partial files; package imports (`@theme/...`) are left for MdxNormaliser. supabase's `<$Partial path=...>` is the separate `resolvePartials`.

**Microsoft Learn without a repo** - `discovery: "mslearn"` walks the per-section sidebar `toc.json` files (space-separated in `discoveryUrl`), resolving relative hrefs and keeping those under `url`; pages answer `Accept: text/markdown`. Used by azure-key-vault since MicrosoftDocs/azure-security-docs went private (2026-10).

**DokuWiki wikis (OpenWrt, FreshTomato)** - use `type: "http"` + `discovery: "dokuwiki"`. DokuWiki has no API and usually no sitemap, but its `?do=index` page renders the full namespace tree server-side: namespace links carry `?idx=<ns>` (colon-form, URL-encoded when nested), page links are ordinary content URLs, so `dokuwiki.ts` BFS-walks the idx pages to enumerate the wiki. The source's `urlExclude` regex doubles as a crawl-time namespace prune (an `idx=X` value is tested as the synthetic page path `<url><X-with-slashes>/`), which is how openwrt drops its ~20 translation namespaces and the 27.5k auto-generated `/packages/` stubs before a single fetch. Page URL shape differs per wiki template: openwrt uses clean root URLs (`/docs/guide`), freshtomato uses PATH_INFO (`/doku.php/page`) - set `url` accordingly, since it's the page-link prefix the crawl accepts. Caps: 2000 idx pages / 20k page URLs.

**incident.io status pages (supabase-status)** - use `type: "http"` + `discovery: "incidentio"` for status pages migrated to incident.io (Next.js on Vercel; status.supabase.com moved in 2026-10, killing the Atlassian Statuspage `/history.json` + `/incidents/<code>.json` endpoints). The proxy API serves a rolling ~3-month window only: `<url>/proxy/<host>/incidents` lists every current incident (no paging - query params are ignored) and `<url>/proxy/<host>/incidents/<id>` returns the full update timeline; `incidentio-converter.ts` renders one `incidents/<id>.md` per incident. Because the window rolls, `ingestFromIncidentio` carries forward every `*.md` from the previous output dir (`DOCS_OUT_DIR/<source>`; fresh wins on collision, origin URLs from the previous `.stamp.json`) so the pre-migration archive (hundreds of root-level `<code>.md` files) survives across fetches - this also keeps the file count inside the regression-guard band.

**MySQL-style manuals published only as GNU info** — use `type: "http"` + `discovery: "texinfo"`. The MySQL Reference Manual isn't markdown or in any git repo, and dev.mysql.com is HTML-only with no sitemap/llms.txt and no content negotiation. The one mirror-able form is the texinfo build shipped as `mysql-X.info.zip`: a single ~4MB archive unpacking to the whole manual (~2,400 nodes). `HttpIngestor.ingestFromTexinfo` downloads + unzips it (via `fflate`, so no system `unzip` dep) and `info-splitter.ts` splits the `0x1f`-delimited nodes into per-node markdown, converting `* Menu:` blocks to bullet-link lists, setext underlines to ATX headings (min-level normalised so the node title is H1), and inline `*note` cross-references to links. Limitation: a handful of labels containing a literal `*` (e.g. `'SELECT *'`) leak the raw `*note` token — ~0.02 per page, cosmetic.

**AsciiDoc / Antora docs (Debezium)** — use `type: "git"` + `format: "adoc"`. The GitIngestor routes the checkout through `asciidoc-converter.ts`, which renders each `modules/ROOT/pages/**/*.adoc` with Asciidoctor.js (pure JS, no Ruby), resolving `include::`/`ifdef::community,product[]`/`xref:`/attributes against the on-disk partials using the `antora.yml` attribute set plus per-page header attributes (so `{connector-name}` resolves inside shared partials), then Turndown → markdown. Cleanup strips Asciidoctor's visible "Unresolved directive" placeholders, rewrites `xref` `.html` targets to `.md`, and drops empty section-anchor links. Conversion lives in the ingestor (not a `DocNormaliser`) because `include::` needs the whole checkout on disk — same rationale as `openapi-converter.ts`. Limitation: Debezium's connector config-property tables are generated from Java at build time and absent from git, so those few fragments don't appear in the mirror.

**CMSIS-SVD register maps (nordic-nrf52840, nordic-nrf52820, artery-at32f405)** - `type: "git"` + `format: "svd"`. GitIngestor routes each checked-out `.svd` (a `paths` entry may be a single file) through `svd-converter.ts` (fast-xml-parser, values kept as strings so hex survives): one `<device>/<PERIPHERAL>.md` per peripheral (H1 `<DEVICE> <PERIPHERAL> - <description>`, base address, interrupts, register summary with offset/absolute address/access/reset, a `## <REGISTER>` field table per register) plus `<device>/index.md` with the peripheral and interrupt tables. Dim arrays expand to per-element summary rows, clusters fold their offsets in, field bits come from `lsb`/`msb`, `bitOffset`/`bitWidth` or `bitRange`, access/reset inherit device -> peripheral -> register -> field, and `derivedFrom` inherits registers but keeps the derived peripheral's own base address and interrupts. Ingestor-side like the AsciiDoc converter, so no `src/index.ts` entry. Use it when a vendor's HTML/PDF manuals are unreachable (docs.nordicsemi.com 403s every non-browser client). WCH CH32 and Nuvoton M480 SVDs have no redistribution terms (2026-11-07) and are not mirrored.

**PDF datasheets and specs (wch-ch32v30x, usb-hid-usage-tables, at32f405)** - `type: "http"` + `format: "pdf"` + `discovery: "pdf"`, `discoveryUrl` = space-separated direct PDF URLs. `pdf-splitter.ts` runs `pdftotext -layout` (poppler-utils: Dockerfile fetcher stage, build.yml fetch step) and splits on numbered, chapter and all-caps headings, falling back to 10-page chunks; each page is H1 `<doc> - <section>`, a `> Source:` line with the page number, then the text in a ```text fence so register tables keep their columns. `[url]` is the PDF URL. A missing pdftotext fails that source, not the build. Heading detection has false positives on register bitfield lines (~20% of sections); harmless for search.

**reStructuredText sources (suricata, mpv, faultier-python, greatfet)** - `type: "git"` + `format: "rst"`. `rst-converter.ts` batch-renders every `.rst` under `rootPath` to HTML5 through a bundled Python + docutils helper (`src/ingestors/rst-render.py`, one process per source like the Jinja helper), then Turndown. Sphinx-only directives (`toctree`, `automodule`, `versionadded`, ...) and roles (`:ref:`, `:func:`, `:term:`, ...) are tolerant stubs so pages render; `:doc:` targets are rewritten to relative `.md` links for the link graph. docutils must exist wherever fetch-docs runs: `py3-docutils` in the Dockerfile fetcher stage, `pip install docutils` in build.yml, and the dev box. A missing python3/docutils fails the source cleanly. Heavily extended Sphinx trees (nRF Connect SDK) are not attempted.

**Sphinx sites mirrored as HTML (build123d, ezdxf, scikit-rf, trimesh, platformio, pyvista)** - `discovery: "toc"` on the index page(s) (`discoveryUrl` may list several, space-separated; toc link extraction accepts single-quoted hrefs, which pydata-sphinx-theme emits). `*.readthedocs.io` answers `Accept: text/markdown`; custom domains return HTML, so autodoc signatures come out of Turndown with `\_` escapes. sphinx_rtd_theme has no `<article>`/`<main>`: set `htmlContentClass: "document"`. `urlExclude: "(genindex|py-modindex|search)\.html$|/_(static|modules|sources|downloads)/"` drops Sphinx artifacts. Keep `tocDepth` at 1 when the index pages already list every autosummary page (pyvista: depth 2 re-crawled ~1,000 API pages sequentially and blew the 10-min deadline). Prefer the `rst` format when the repo's RST is plain docutils.

**Code and rule files as fenced text** - `format: "txt"` walks `.txt .h .py .cpp .kicad_dru .toml .cue` (`TXT_EXTENSIONS` in GitIngestor plus `TxtNormaliser.supports`; add an extension to both). Used by libhmk-src, nvapi, kicad-druid-src (KiCad design-rule files) and vector-reference (Vector's component reference lives in CUE; the Hugo pages in `vector` are shells).

**Go libraries without markdown docs** — use `type: "git"` + `format: "godoc"`. The GitIngestor walks `.go` files (skipping `_test.go`, `z*.go`, `*.pb.go`, `*_string.go`, `*_generate.go`) and `GoNormaliser` extracts the package decl, package-level doc, and exported declarations (func/method/type/const/var) with their doc comments into one markdown file per source `.go` file. Methods are grouped under `## Methods on T` per receiver. Used by `miekg-dns` (v1, GitHub) and `miekg-dns-v2` (v2, Codeberg). Limitation: the extractor is a line-based state machine, not a Go AST parser; inline `struct{...}` return types in function signatures are a known edge case that may truncate a signature mid-type. Acceptable trade-off for avoiding a Go toolchain dep in the fetcher stage.

**MkDocs with jinja/macro/snippet directives (TRaSH-Guides)** - use `type: "git"` + `format: "markdown"` + `resolveTrashGuides: true`, with `paths: ["docs", "includes"]` (the `includes/` tree lives at repo root and is referenced by the directives, so it must be sparse-checked out). `trash-guides-converter.ts` (invoked from GitIngestor) resolves the four MkDocs preprocessing layers the upstream commits raw: `--8<-- "..."` snippets (pymdownx.snippets, base repo root), `{! include-markdown "..." !}` (base: including file's dir), `[[% include 'json/...' %]]` / `[[% filter indent(width=N) %]]` (mkdocs-macros), and `{{ sonarr['...']['...'] }}` lookups (markdownextradata, against `docs/json/**`). Resolution semantics were verified against each plugin's source. The two `Guide-Sync/*-cf-groups.md` pages are full Jinja control-flow templates (`{% for %}`, macros) with Python object semantics (`.split()`, `.get()`, `namespace()`, string `in`) that no JS template engine supports, so they are batch-rendered through a bundled Python + Jinja2 helper (`src/ingestors/jinja-render.py`, invoked via `node:child_process`). Jinja2 must be present wherever fetch-docs runs: `python3 py3-jinja2` in the Dockerfile fetcher stage, `pip install jinja2` in the release workflow's fetch step, and the local dev box. A missing python3/jinja2 degrades gracefully (the templates stay raw) rather than failing the source.

**AWS is the last entry in the SOURCES array on purpose** — it discovers ~14k page URLs across ~80 services and is by far the slowest source. Placing it last means earlier batches don't wait behind it.

**Two helper scripts in `scripts/` for evaluating new sources** (devDeps: playwright, @mozilla/readability, jsdom):
- `pnpm tsx scripts/probe-sources.ts > /tmp/probe.tsv` — checks every existing source for archive / llms-full / llms.txt / known-git availability. Used to drive the v0.14.0 mass migration.
- `pnpm tsx scripts/audit-sources.ts > /tmp/audit.tsv` — fetches each `format: "html"` source's sample page two ways (plain `fetch` + Turndown, then headless Chromium + Mozilla Readability) and classifies KEEP / JS / DROP. Useful when adding a JS-heavy source to confirm a sitemap-based ingestion will yield usable markdown before committing to it.

## Single source of truth

The SSH server is the canonical source for all agent configuration. The `agents` command dynamically generates instructions using live container data (source list, file counts).

```bash
ssh docs.erfi.io agents              # AGENTS.md (default, raw SSH patterns)
ssh docs.erfi.io agents opencode     # AGENTS.md for OpenCode (references custom docs_* tools)
ssh docs.erfi.io agents claude       # CLAUDE.md
ssh docs.erfi.io agents cursor       # .cursorrules
ssh docs.erfi.io agents gemini       # GEMINI.md
ssh docs.erfi.io agents skill        # SKILL.md with YAML frontmatter
ssh docs.erfi.io agents help         # show all formats
```

When updating server features, redeploy and re-pull configs. Output is dynamic — file counts, source lists, and tool references are always current.
